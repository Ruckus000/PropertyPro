The unit roster is the structural backbone of an apartment community in PropertyPro. Every lease, work order, package, and assessment ties back to a unit. Keep the roster clean and every downstream workflow becomes easier.

## What a unit record holds

- **Unit number** — the canonical identifier residents and staff use
- **Building** — optional free text for multi-building communities (e.g. "Tower A")
- **Floor** — optional, useful for sorting and grouping

There is no unit status field in the app. Whether a unit is vacant is derived from lease state on the Leases page (**Vacant Units** filter). The units table also shows a **Rent** column for apartments, pulled from each unit's active lease — it isn't a field you set on the unit itself.

## Adding units

<StepByStep>
<Step title="Open Units → Add unit">
Click the Units link in the sidebar, then **Add unit**.
</Step>

<Step title="Enter the unit details">
Unit number is required and must be unique in the community. Building and floor are optional.
</Step>

<Step title="Save">
The unit appears in the roster immediately. You can now attach a lease, log work orders, or assign packages.
</Step>
</StepByStep>

## Bulk import

<Callout type="info" title="Coming soon">
CSV bulk import for units isn't available yet. For now, add units one at a time with **Add unit** (above). When bulk import ships, you'll be able to download a Units CSV template, fill in one row per unit (unit number, building, floor), and upload the whole roster at once — useful for initial setup, a major roster sync, or renumbering during a renovation or new-building addition.
</Callout>

## Buildings and groupings

PropertyPro does not have a separate building entity. Each unit has an optional **Building** text field — use the same value on multiple units to group them (for example, "Tower A" or "Garden Building"). This helps staff sort and identify units but does not enable building-targeted announcements, maintenance routing, or visitor routing.

## Handling vacancies

When a unit goes vacant:

<StepByStep>
<Step title="Close out the move-out">
Complete the [move-out checklist](/help/apartment/move-in-move-out-checklists). Terminate the lease on the Leases page.
</Step>

<Step title="Schedule turnover work">
Create work orders for any cleaning, paint, repair, or carpet replacement needed before re-renting.
</Step>

<Step title="When re-rented, create a new lease">
Create a new lease record on the Leases page for the next tenant.
</Step>
</StepByStep>

## Renumbering and renaming

If you renumber units (for example, post-renovation), unit edits are not available in the UI yet — the Units page is read-only after creation. Contact your platform administrator or use the API if renumbering is required.

## Lease expirations

The dashboard shows a lease-expirations card to help you plan renewals and turnover. There is no occupancy-rate or unit-mix report on the Units page.

## Common patterns

- **Adding units in a new building** — add units one at a time with **Add unit**, using the same **Building** value on each row.
- **Combining units** — keep historical unit records intact; note the combined unit in lease or work-order records as needed.

## Tenant linkage

Each tenant on a lease is linked to a unit. When you offboard a tenant:

- Their access to the unit ends with the lease termination.
- Vacancy is visible on the Leases page when no active lease exists on the unit.
- The tenant's PropertyPro account stays (they can keep using it for other communities).

This separation — units are owned by the community, accounts are owned by individuals — keeps the audit trail correct as residents move in and out.
