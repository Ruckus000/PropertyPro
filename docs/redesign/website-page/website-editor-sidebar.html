PM "Website" Editor — Sidebar (app chrome)

The navigation rail that surrounds the Website editor, exported on its own so a redesign renders the surrounding chrome correctly. This is the real, on-route sidebar — not the approximation drawn inside website-editor-mockup.html.

Why this rail (and not the community one). The editor lives at /pm/settings/website. Because that path starts with /pm/, the app shell sets isPmContext = true and renders the PM-portal rail from PM_NAV_ITEMS — four items only: Communities · Website (active) · Templates · Reports. The richer community rail (Dashboard + Community / Management / Admin) is the entry point you click Website from — it is not what shows on the editor route.

Fidelity. Markup and classes come from NavRail.tsx, SidebarTenantSwitcher.tsx (static brand header), AppSidebar.tsx (profile footer) and PlanBadge.tsx; icons are the exact lucide-react v0.501.0 paths the app imports; colors, radii and the 18px root are the "Florida Modern" tokens from packages/tokens. Redesign inside the constraints in website-editor-design-system.md.

Sample data  Community name “Sunset Condos” and the profile block (Jordan Rivera · Property Manager · Professional) are placeholders — structure is real, the specific strings are illustrative.

  • Active-state signal is threefold and lockstep: background fill + bolder label/darker text + the 4px coral left indicator bar. Never color alone.
  • Collapse toggle flips the rail 260↔72px; collapsed shows icons only (labels clipped) and the brand/profile text is hidden. Uses NavRail's own 20×20 panel icon.
  • Header is static here — the PM portal always shows the brand block (no community switcher popover), unlike multi-community members in community context.
  • Focus ring on every item: 2px --border-focus (coral) at 2px offset. Do not suppress.
  • Plan pill reflects the community's plan; on Essentials it reads "Essentials" and Pro-only surfaces elsewhere carry a gold "Pro" PlanBadge.
