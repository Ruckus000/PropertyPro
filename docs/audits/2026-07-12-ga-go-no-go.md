## Remaining gate — live Stripe test-mode E2E (external secrets)

**Why not automated:** the flow's first hop creates a real Stripe Checkout session, so it needs a test-mode `STRIPE_SECRET_KEY` + webhook secret + checkout return URLs. CI and default local shells deliberately omit these; the automated suite therefore covers the server-side provisioning/lifecycle logic (unit + integration) but not the hosted-checkout browser hop.

**To close (one-time, on staging), per [`2026-07-11-stripe-cancel-smoke.md`](2026-07-11-stripe-cancel-smoke.md):**
1. Configure test-mode Stripe secrets in `.env.local`; run `stripe listen --forward-to localhost:3000/api/v1/webhooks/stripe`.
2. `signup → community details → Stripe Checkout (test card 4242…) → /signup/checkout/return?session_id=…` → confirm the community is `trialing` and dashboard access works.
3. `stripe trigger customer.subscription.deleted` → confirm `subscription_status`, `next_reminder_at` (day-5), and the 7-day-grace email.

**Record result here when performed:**

> _Live Stripe test-mode E2E: ⬜ not yet run — pending Stripe test secrets._
